# Voice-Controlled Design Canvas

A browser-based design tool in which canvas operations that normally require a keyboard
modifier held while the mouse acts (panning and multi-select) can be carried out by
speech.

Command recognition uses a DistilBERT intent classifier fine-tuned on a 30-command
taxonomy developed for this project, exported to ONNX and run entirely in the browser.

**[Demo video](https://youtu.be/tscQUrYPx5I)**

---

## Motivation

Most design tools assume two hands for their core canvas gestures. Panning requires the
space bar held while dragging. Multi-select requires shift held while clicking. A user
who cannot hold a key and click simultaneously has no route to either operation.

Multi-select is additionally a prerequisite for aligning, grouping, distributing and
recoloring more than one object, so the restriction extends well beyond the two gestures
themselves.

The number of physical actions is also relevant. Selecting eight shapes with a mouse
requires eight clicks. Selecting them by voice requires one phrase, irrespective of the
number of objects involved.

The tool remains fully operable by mouse and toolbar. Voice is an additional route
rather than a replacement, since an interface reachable only by speech would introduce
its own accessibility barrier.

## Architecture

```
spoken phrase
  -> Web Speech API (Chrome)         -> transcript
  -> DistilBERT intent classifier    -> intent, confidence
  -> rule-based slot extractor       -> parameters (color, direction, number, edge)
  -> confidence gate (0.60)          -> execute or refuse
  -> command handler                 -> canvas update
```

Speech recognition is provided by Chrome's Web Speech API, which transmits audio to
Google's servers and returns a transcript. It is not part of this project's
contribution. The intent classifier, slot extraction, confidence gating and the 30
command handlers were developed for this project. The classifier runs locally in the
browser; the microphone requires a network connection.

Intent classification is distinct from dictation. A 30-class classifier identifies which
command was spoken, but cannot handle arbitrary content such as "change this text to
Rafia", because the set of possible strings is unbounded. Text content is therefore
edited through a panel field. This is an architectural boundary rather than an
unimplemented feature.

## Dataset

| Property | Value |
|---|---|
| Training phrases | 544 |
| Labels | 30 |
| Phrases per label | 18 to 20 |
| Held-out evaluation set | 60 phrases, 2 per label, absent from training |
| Schema | `phrase,label` |

The 30 commands were selected by identifying the canvas operations least reachable with
one hand. Seed phrases were written for each label, then expanded into paraphrase
variations with AI assistance and curated. Both CSV files are generated by
`build_dataset.py`; edits are made to the script rather than to the CSV files.

`command_taxonomy.md` documents the label design, including a table of deliberately
confusable label pairs identified before training.

## Model

| Property | Value |
|---|---|
| Base model | DistilBERT, fine-tuned for 30-class classification |
| Held-out accuracy | 87% to 93% across three training runs |
| Held-out macro F1 | 92.9% on the saved run |
| Confidence threshold | 0.60 |
| Export | ONNX, int8 dynamic quantization |
| Runtime | transformers.js v3, `dtype: 'q8'`, in-browser |

### Training variance

The model was trained three times with identical data, code, settings and seed. Held-out
accuracy ranged from 87% to 93%, and the optimal confidence threshold moved between 0.40
and 0.70 across those runs. The repeated runs made it possible to separate stable errors,
which recur in every run and indicate genuine gaps in the dataset, from training
variance.

### Confidence gating

Predictions below 0.60 are refused rather than executed. For a user with limited hand
mobility, an incorrect action carries a higher cost than a repeated command, since
reversing an incorrect action is itself a manual multi-step operation. The threshold is
a property of the specific trained model and requires re-derivation after any
retraining.

## Results

A basic mobile UI mockup was built within the tool and every command recorded in the
activity log.

Of 32 voice commands issued, 27 executed correctly and 5 failed. All five failures
originated in speech recognition rather than intent classification. Chrome transcribed
"right" as "write", "white" as "bite", and "grey" as "great". In each case the
classifier responded correctly to the text it received.

Three of the five mis-transcriptions were intercepted before any action occurred: twice
because a required direction parameter was absent, and once because the confidence gate
refused a prediction of 0.29. Two of 32 commands (6%) produced an unintended action,
both reversible in a single step.

Full method, figures and caveats are documented in [RESULTS.md](RESULTS.md).

## Limitations

Twelve limitations are documented in [LIMITATIONS.md](LIMITATIONS.md). The principal
ones are listed below.

- **Register sensitivity.** The model generalizes to unseen phrasings written in the
  same register as the training data, but performs substantially worse on conversational
  phrasings such as "stick these together" or "scoot it over to the left". The held-out
  set shared a register with the training data and therefore overstated generalization.
- **Spoken dimensions are not supported.** "Make a 1920 by 1080 rectangle" is classified
  correctly but falls below the confidence threshold, because no training phrase
  contains two numbers. Exact dimensions are set through the properties panel.
- **No multi-turn slot filling.** When a required parameter is absent the tool reports
  it, but cannot accept the answer in isolation. The full command must be repeated.
- **Ambiguity within the command vocabulary.** "Move the canvas up" admits two valid
  interpretations, and "align horizontally" carries opposite meanings in design-tool
  terminology and in ordinary use. In these cases the classifier is correct and the
  vocabulary is ambiguous. Additional training data would not resolve it.
- **Single-participant evaluation.** All testing was carried out by the author. No study
  has been conducted with participants who have limited hand mobility.

## Installation

The model must be served over HTTP. Opening `canvas.html` directly from the file system
will not load it.

```
git clone https://github.com/s-rafia/voice-controlled-design-tool
cd voice-controlled-design-tool/web
python -m http.server 5500
```

Open `http://localhost:5500/canvas.html`.

The microphone requires Chrome or Edge and a network connection. All other functionality
operates offline once the model has downloaded.
